# Refactor Result Retrieval & Assessment

This workflow retrieves the code generated by Jules, verifies it against the tests, and produces a quality assessment report.

## 1. Context Retrieval
*   **Global Constraint:** You are an ASSESSOR, not a DEVELOPER in this workflow. You must **NOT** write, edit, or fix any code. Your job is *strictly* to retrieve and assess.
*   **Input:**
    *   **Session ID** (from `refactor-execute`).
    *   **PR Number** (provided by User/Jules).
*   **Action (Code):**
    *   Execute: `gh pr checkout [PR_Number]`
    *   Verify: `git status` / `git log -1`.
*   **Action (Reasoning):**
    *   Execute: `jules remote pull --session [Session_ID]` (DO NOT use `--apply`).
    *   *Analysis:* Inspect the downloaded artifacts (logs/conversation.md) to follow Jules' reasoning and decision path.

## 2. Implementation Review (Static)
*   **Context:** Read the **Original Task File** used in `/refactor-execute`.
*   **Action:**
    *   Use `fd` or `ls` to verify new files exist (e.g., `metrics/core/fx_access.py`).
    *   Use `view_file` to inspect the implementation of key logic.
    *   **Check:** Does the code match the "Detailed Steps" in the Task File?
    *   **Check:** Are the "Deprecations/Deletions" performed?

## 3. Verification (Dynamic)
*   **Action:** Run the tests specified in the "Test Plan" of the Task File.
    *   Example: `pytest tests/metrics/core/test_fx_access.py`
    *   Example: `pytest tests/integration/test_something_else.py`
*   **Constraint:** Do **NOT** attempt to fix code if tests fail. Just report it.

## 4. Local Quality Gate
*   **Action:** Run strict local linting to ensure no regressions or environment mismatches.
    *   Python: `ruff check .`
    *   TypeScript (if applicable): `npm run lint:ts` and `npm run typecheck`
*   **Constraint:** Do **NOT** attempt to fix linting errors. Just report them.
*   **Output:** Report pass/fail status in the Assessment Report.

## 5. Assessment Report Generation
*   **Goal:** Create a feedback loop for the next phase.
*   **Target File:** `tasks/post_execution_[phase_name].md`.
*   **Action:**
    *   **Check Existence:** checking if the file already exists (e.g. `ls tasks/post_execution_[phase_name].md`).
    *   **If Exists:** **APPEND** to the file. Add a Level 1 Header (`# Assessment: PR #[Number] - [Step Name]`) and the content below it.
    *   **If New:** **CREATE** the file. Add the Header and content.
*   **Content:**
    1.  **Execution Summary:** (Success/Failure, files changed, link to PR).
    2.  **Quality Check:**
        *   Does it follow the `refactor_calculations.md` architecture?
        *   Did it handle the "Breaking Changes" correctly?
        *   Did local linting pass?
    3.  **Test Results:** Output of the `pytest` run.
    4.  **Recommendations:** Code cleanup, missing docs, or adjustments needed for the *next* phase.

## 6. Final Handover
*   Ask user: "Assessment complete. Shall we proceed to `/refactor-estimate` for the next Phase, or do you want to manually refine the current code?"
